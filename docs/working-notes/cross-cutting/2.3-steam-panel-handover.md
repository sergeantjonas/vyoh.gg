## Hard-earned lessons — do not re-trip

### 1. Ancestor opacity suppresses descendant `backdrop-filter`

Any `opacity < 1` on an ancestor (Motion `initial={{ opacity: 0 }}` is the common offender) flattens descendants into a single raster buffer, killing every descendant `backdrop-filter` until opacity reaches 1.0. Symptom: frosted tiles look transparent at first, then suddenly snap to frosted ~300ms in (matching the animation duration).

**Rule for the Steam panel:**
- Never animate `opacity` on a wrapper above a frosted descendant.
- Use `y` / `scale` entrance animations only.
- Self-opacity on a frosted element itself is fine (renders as smooth fade-in of the frosted look).

Reference: [[ancestor-opacity-suppresses-backdrop-filter]] memory. Bit us 5+ times across `$matchId.tsx`, `$championKey.tsx`, `match-spell-casts.tsx`, `match-damage-profile.tsx`, `match-owner-stats.tsx`, `match-review-view.tsx`. **The Steam panel will have the same trap.**

### 2. `animation-timeline: view(block)` breaks in nested scroll containers

The `.view-entry` CSS class in [motion.css:226-230](../../../apps/web/src/styles/motion.css#L226-L230) is a scroll-driven opacity-0→1 entrance animation. Inside the panel's own scroll container, it leaves bottom-of-panel tiles stuck at partial opacity (the "champion-detail vignette" symptom that took 4+ rounds to diagnose).

**Already fixed** in CardShell via `!frosted && "view-entry"` ([card-shell.tsx](../../../apps/web/src/components/card-shell.tsx)). The Steam panel inherits the fix automatically because CardShell is what backs FactCard. **Do not** add `view-entry` to new in-panel components.

Reference: this session's debugging arc (the user's white-background isolation was the key — opacity bug invisible against the dark splash).

### 3. Glass is a boundary layer — don't nest it

Apple HIG + NN/g converge: one level of glass between background and content. A tile is frosted when it sits *directly* over an unstructured backdrop (splash, screenshot, atmosphere). Tiles nested inside a frosted card stay solid. Frosting everything makes glass stop reading as glass.

**For the Steam panel:**
- Panel chrome is solid `bg-card` + baked `chromeBackdropUrl` (CSS background-image) — NOT a live frosted layer. This is intentional; the panel-internals get the glass.
- Steam game-detail tile components that consume `FactCard` (in `apps/web/src/steam/game/`) should pass `frosted={true}` only when rendered in-panel. The same components rendered on a page-grounded surface omit it.
- Don't add `backdrop-filter` to the panel chrome itself. Don't add `backdrop-filter` to a `<div>` wrapping FactCards. One layer, not two.

Full rule: [repo-conventions.md § Tile background](../../repo-conventions.md). KB: [`~/.claude/knowledge/frontend-2026/01-css-and-styling.md` § Glassmorphism](file:///home/node/.claude/knowledge/frontend-2026/01-css-and-styling.md).

### 4. Don't blame the className when the issue is opacity / animation

The vignette debugging took several rounds because the first reflex was "the frosted className isn't applied". It WAS applied — the bug was a scroll-driven opacity animation. **Isolation tests beat hypothesis tests.** When something visually looks wrong:

1. Change the backdrop to a uniform high-contrast color (e.g., pure white) — instantly reveals opacity gradients that hide against busy splash.
2. Check ancestor opacity / filter / mix-blend-mode before assuming the descendant's className is wrong.
3. Use DevTools Layers panel — composite layers visualise stacking contexts and accelerated transforms/opacity.
4. Use DevTools Computed panel to walk up the ancestor tree checking opacity, filter, mask-image.

Reference: this session's vignette arc + [[instrument-before-hypothesise]] memory.

### 5. Firefox VT is engine-gated off — don't fix that

Firefox's screenshot pipeline doesn't capture `backdrop-filter` (Mozilla Bug 1657997, unfixed since 2020). Router-level View Transitions on Firefox cause every frosted surface to lose its blur during the OLD→NEW snapshot crossfade. Gate exists at [`apps/web/src/lib/view-transition-nav.ts` § supportsViewTransitions](../../../apps/web/src/lib/view-transition-nav.ts).

**For Steam panel:** Steam already has its own WebKit VT bypass in [navigation-type.ts](../../../apps/web/src/lib/navigation-type.ts) (`isWebKit()` returns false from `getNavigationType`). Don't try to re-enable VT for Steam on either engine without explicit reason — both bypasses are deliberately documented (Firefox + WebKit have different bugs/cost cliffs).

The rect-morph fallback in `match-row.tsx` / `match-hero.tsx` handles row→hero animation when VT is off. Steam library should use the same pattern (probably already does — verify).

### 6. `prefers-reduced-transparency` is honoured globally

A11y users with macOS Reduce Transparency, iOS Increase Contrast, or Windows Transparency get all `backdrop-filter` dropped + translucent surfaces promoted to solid via a `@media` block in [index.css](../../../apps/web/src/index.css). **You don't need to wire this up for new frosted recipes** — the selector matches `[class*="bg-card/"]`, `[class*="bg-popover/"]`, `[class*="bg-background/"]`. If you add a new translucent surface using a different color token, extend the selector.

### 7. HD splash preloads need `fetchPriority="high"`

Bare `new Image(); img.src = url` defaults to low/medium fetch priority. The HD splash (~500KB-1MB) becomes the panel chrome's primary visual — set `img.fetchPriority = "high"` before assigning src. Already applied at:
- [`apps/web/src/lol/_shared/assets/splash-backdrop.tsx`](../../../apps/web/src/lol/_shared/assets/splash-backdrop.tsx)
- [`apps/web/src/lol/matches/match-row.tsx`](../../../apps/web/src/lol/matches/match-row.tsx)
- [`apps/web/src/lol/champions/champion-table.tsx`](../../../apps/web/src/lol/champions/champion-table.tsx)

**For Steam panel:** the Steam game hero/screenshot is the equivalent visual. Apply `fetchPriority="high"` to its preload (probably in the library tile row's hover prefetch). Steam screenshot URL helper lives in [`apps/web/src/steam/`](../../../apps/web/src/steam/) — find the equivalent of `championHdSplashUrl`.

### 8. `useHoverPrefetch` fires on pointerdown too

[`apps/web/src/lib/use-hover-prefetch.ts`](../../../apps/web/src/lib/use-hover-prefetch.ts) — 150ms hover delay OR instant on pointerdown. So even fast clicks get prefetch on click. Use this pattern for Steam library rows. **Cold-load (deep link, command palette) has no prefetch** — the panel will pay the load cost. If Steam screenshot cold-loads feel slow, consider adding a `<link rel="preload" as="image" href={url} fetchpriority="high">` via the route's `head()` factory.

### 9. TS-server inline diagnostics lag

After codegen (Prisma, graphql-codegen) OR fast edits, the inline TS diagnostics surface stale errors that resolve on a fresh `pnpm run typecheck:cc`. **Don't loop edits to chase phantom errors** — re-run the project typecheck before assuming a real bug. Bit me 3 times this session.

### 10. Tooling discipline (enforced by hooks)

- **`ugrep` / `bfs` not `grep` / `find`** (hooks block bare invocations).
- **`Read` with `limit` on files > 150 lines** (hooks block it otherwise).
- **`Edit` / `Write` not `sed` / `awk`** — keeps file state tracked.
- **Don't re-read the same file 3+ times** (hook nudges; usually means use `offset` + `limit` instead).
- **Use project scripts**: `pnpm run check:cc` (lint), `pnpm run typecheck:cc`, `pnpm run test:cc`. Wrap with `tokf err` / `tokf test` for compressed output.
- **`pnpm test:cc` filters suite-level results but not per-test framework-logger output.** When a green run still floods context, follow up with `pnpm test:cc 2>&1 | grep -E "(Test Files|Tests|FAIL)" | tail -5`.

### 11. Commit discipline

- Style: `type: description` lowercase, no `(scope)` parens, no ticket numbers, never `Co-Authored-By`.
- Never push to remote.
- Owner runs concurrent Claude Code sessions — your `git add .` may grab their unstaged work. **Always `git status -s` before staging**, and explicit-list files rather than wildcards when the working tree has unexpected contents (this session's commit 1 accidentally grabbed the user's queue-id work — they had to add a clarifying commit).
- Tests in the same commit as the feature/fix (standing bar across this project).

### 12. Don't second-guess owner observations

When the user says "this is dimming/popping/looking weird" — take it at face value. Don't propose alternate interpretations. Investigate, instrument, then act. Reference: [[don't second-guess owner observations]] memory.

### 13. Reproduce-then-theorize on multi-engine bugs

After one failed visual fix, **write a probe before shipping a second guess**. Headless Playwright with computed-style dumps; mid-transition snapshots; uniform-color isolation backgrounds. The user's white-background test this session cracked the vignette debug in one screenshot after I'd burned 3 rounds guessing. Reference: [[reproduce-then-theorize-on-multi-engine-bugs]] memory.
