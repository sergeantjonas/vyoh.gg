- **Ingestion cron reliability** — **three self-sealing gates fixed 2026-08-05**, opened by a real symptom: nine Steam achievements earned in 24 h were not ingested at all. The defect class is *a cached upstream fact that gates downstream work and is only re-derived by a rare cron*. Here a game bought pre-release recorded `achievementCount = 0`, all four unlock paths gate on `> 0`, and the boot backfill skips rows that exist — so the more it was played, the more often the hourly poller saw it and no-opped. `@nestjs/schedule` does not replay a missed fire, and three measurements showed the long-interval crons have effectively never run on the dev box: the weekly schema cron has **no** 05:00 timestamp in the table (both recorded runs were boot backfills), the 2026-08-02 rarity cron didn't fire, and the tag catalog's newest row is 2026-07-15 against a monthly cron. Fixed: recently-played re-checks empty schemas before its unlock loop, the tag poller's boot check reads catalog *age* not row count, `refreshSchemas` guards its write per appid (one failure used to abort every appid behind it), and `refreshUnlocksForGame` asserts `count > 0` rather than `!== 0` on a nullable column. **Arc complete 2026-08-06:** all four long-interval pollers now select on age rather than on a wall-clock fire — schema and rarity daily against a 7-day window, enrichment daily against 30 days OR'd with its existing `logoPath IS NULL` predicate, tag catalog on boot. (Rarity gained a second, shorter window on 2026-08-13 — 1 day for titles released within 60 — because launch-window drift is ~100× steeper than settled drift and weekly sampling loses it permanently; see the drift arc.) The boot pass is the load-bearing half, since a daily cron at 05:00 on a machine that is off at 05:00 still never fires; the daily tick carries it once hosting makes the process continuous. Each was verified against the live database rather than mocks — rarity's first run found the backlog the never-fired Sunday crons had left and drained it 40 per pass instead of one 158-call burst. Residual risk is a day rather than a week or a month.
